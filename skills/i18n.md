# i18n - t() lookups driven by `<html lang>`

A translation file is a plain module. It default-exports a nested object of strings.
`t('todo.title')` finds a message by its dotted path. The current language **is** the `lang`
attribute on `<html>`. The direction follows the language in `<html dir>`. An app declares its
translations once in `init`. A section that loads lazily declares its own in `area`.

```js
// locales/en.js
export default { todo: { title: 'Todos', greeting: 'Hi, {name}' } }
```

```js
import { init, mount } from 'imp'
import { computed } from 'imp/state'
import { dir, lang, missingMessages, setLang, t } from 'imp/i18n'

await init({
  theme: 'imp-light',
  translations: { en: () => import('./locales/en.js'), pl: () => import('./locales/pl.js') },
})
mount('#app', app())
```

## `init(options)` - every option is optional

| Option         | What it does                                                                                            |
| -------------- | ------------------------------------------------------------------------------------------------------- |
| `theme`        | imp applies it with `applyTheme`. Give a built-in name or your theme object, see [theming](theming.md). |
| `translations` | a map of language code to loader. imp calls the loader of the starting language only.                   |
| `lang`         | the starting language. The default is `<html lang>`, then the language of the browser.                  |
| `dir`          | pins the direction for the whole app. Leave it out and the direction follows the language.              |

`init` is `async` and loads before the first paint. `await` it before `mount`. This is the only
place where an app declares its translations.

## The API

| Call                       | Notes                                                                    |
| -------------------------- | ------------------------------------------------------------------------ |
| `t(key, values?)`          | a dotted path. imp fills a `{name}` placeholder from `values`.           |
| `await setLang('pl')`      | loads the messages of that language, writes `<html lang>` and swaps      |
| `lang`                     | a read-only state: `get`, `watch`, `text`, `view`                        |
| `dir`                      | a read-only state, `'ltr'` or `'rtl'`, derived from the script           |
| `missingMessages()`        | the reserved `imp.` keys that the active language does not translate yet |
| `defaultMessages(flatMap)` | registers default wording for the keys of your own component             |

## Rules an agent gets wrong

- **Bind translated text through `lang`, never through a bare `t()`.**
  `h1(lang.text(() => t('todo.title')))` localizes again in place. `h1(t('todo.title'))` freezes at
  the language that was active when imp built the node. For a translated **prop**, write
  `button({ 'aria-label': computed([lang], () => t('todo.add')) }, '+')`.
- **`setLang` is async. Always `await` it**, in app code and in a test.
- **`t()` never throws.** For a missing key it returns the key itself and warns once. For a key with
  default wording it returns that wording.
- **`t()` interpolates. It does not pluralize or format.** Use `Intl` for a number and a date, then
  pass the result in: `t('todo.remaining', { total: new Intl.NumberFormat(lang.get()).format(n) })`.
  imp leaves a placeholder with no matching value as it is.
- **Only the active language is in memory.** A key that is missing from it cannot fall back to the
  text of another language. Every declared language must carry every key that the app asks for. A
  regional code also loads its base language and shadows it. So `en-GB` can be three overrides. An
  undeclared language falls back to the first declared language.
- **Put the messages of each area under its own top-level key**, such as `admin.users.title`. All
  messages share one namespace, and on a collision the last loaded message wins.
- **Anything that lives longer than an area must read from the messages of the app.** A header and a
  toast queue are examples. The keys of an area stop resolving when you leave the area.
- **imp does not store the language.** Store the choice yourself and pass it back as
  `init({ lang })`.

## Component wording

A standard component of [std](std.md) finds its words under an `imp.` key, and falls back to
English. So the components read correctly with no translation file. When you write that key in your
own files, your text wins, per key and per language:

```js
// locales/pl.js
export default { imp: { state: { empty: 'Nic tu jeszcze nie ma' } } }
```

| Key                   | Read by                                | Falls back to    |
| --------------------- | -------------------------------------- | ---------------- |
| `imp.state.empty`     | `emptyState`                           | Nothing here yet |
| `imp.state.noResults` | `emptyState({ variant: 'noResults' })` | No results       |

Your own component carries wording the same way, with `defaultMessages`. Pass a **flat** object that
maps a dotted key to a string. Call it where the component defines itself. Do not call it at module
top level, so an unused module has no side effect:

```js
let create = null
export const trialNotice = (...args) => {
  if (!create) {
    defaultMessages({ 'billing.trialEnded': 'Your trial has ended' })
    create = component('my-app-trial-notice', definition)
  }
  return create(...args)
}
```

## Direction

`init` sets `<html dir>`, and every `setLang` changes it. The direction comes from the **script**.
So `az-Arab` is rtl and `az-Latn` is ltr. Write your CSS in logical properties, such as
`margin-inline-start`, `padding-inline-end`, `inset-inline-start` and `text-align: start` or
`text-align: end`. One stylesheet then serves both directions. `flex` and `stack` align with
`'start'` and `'end'`, never with `'left'` and `'right'`, and they mirror themselves. Never reverse
a child list by hand against `dir`. To pin the whole app, use `init({ dir: 'ltr' })`. To pin one
element, use `pre({ dir: 'ltr' }, code)`. For text that a user types, let the browser decide with
`p({ dir: 'auto' }, comment.body)`.

## Area translations

An area, see [routing](routing.md), declares its own messages next to its routes. When you enter the
area, imp loads the one file that matches the current language, before the first screen of the area
paints. When you change language, imp loads the messages of the area with the messages of the app.

```js
export default area({
  routes: { '/': () => dashboard() },
  translations: { en: () => import('./locales/en.js'), pl: () => import('./locales/pl.js') },
})
```

## Testing

See [testing](testing.md) for the runner.

```js
beforeAll(() => init({ translations: { pl: () => import('./locales/pl.js') } }))

test('greets in the active language', async () => {
  await setLang('pl')
  expect(t('greet')).toEqual('Cześć')
})
```
