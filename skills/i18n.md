# i18n - t() lookups driven by `<html lang>`

Translations are plain modules default-exporting a nested object of strings. `t('todo.title')` looks
a message up by dotted path. The current language **is** the `lang` attribute on `<html>`; the
direction follows it in `<html dir>`. Declared once in `init` for the app, and in `area` for a
lazily loaded section.

```js
// locales/en.js
export default { todo: { title: 'Todos', greeting: 'Hi, {name}' } }
```

```js
import { init, mount } from 'imp'
import { computed } from 'imp/state'
import { dir, lang, missingMessages, setLang, t } from 'imp/i18n'

await init({
  theme: 'imp-light',
  translations: { en: () => import('./locales/en.js'), pl: () => import('./locales/pl.js') },
})
mount('#app', app())
```

## `init(options)` - all optional

| Option         | What it does                                                                                |
| -------------- | ------------------------------------------------------------------------------------------- |
| `theme`        | applied with `applyTheme` - a built-in name or your theme object; see [theming](theming.md) |
| `translations` | language code → loader. Only the starting language's loader is called.                      |
| `lang`         | the starting language; defaults to `<html lang>`, then the browser's language               |
| `dir`          | pins the direction for the whole app; left out it follows the language                      |

`init` is `async` and loads before the first paint - `await` it before `mount`. This is the only
place an app declares its translations.

## The API

| Call                       | Notes                                                               |
| -------------------------- | ------------------------------------------------------------------- |
| `t(key, values?)`          | dotted path; `{name}` placeholders filled from `values`             |
| `await setLang('pl')`      | loads that language's messages, then writes `<html lang>` and swaps |
| `lang`                     | read-only state: `get`/`watch`/`text`/`view`                        |
| `dir`                      | read-only state, `'ltr'`/`'rtl'`, derived from the script           |
| `missingMessages()`        | reserved `imp.` keys the active language does not translate yet     |
| `defaultMessages(flatMap)` | register default wording for your own component's keys              |

## Rules an agent gets wrong

- **Bind translated text through `lang`, never a bare `t()`** -
  `h1(lang.text(() => t('todo.title')))` re-localizes in place; `h1(t('todo.title'))` freezes at the
  language present when it was built. For a translated **prop**:
  `button({ 'aria-label': computed([lang], () => t('todo.add')) }, '+')`.
- **`setLang` is async - always `await` it**, in app code and in tests.
- **`t()` never throws.** A missing key returns the key itself and warns once; a key with default
  wording returns that wording.
- **`t()` interpolates, it does not pluralize or format.** Use `Intl` for numbers and dates and pass
  the result in: `t('todo.remaining', { total: new Intl.NumberFormat(lang.get()).format(n) })`. A
  placeholder with no matching value is left as-is.
- **Only the active language is in memory** - a key missing from it cannot fall back to another
  language's text. Every declared language carries every key the app asks for. A regional code loads
  its base language too and shadows it (`en-GB` can be three overrides); an undeclared language
  falls back to the first one declared.
- **Namespace each area's messages under its own top-level key** (`admin.users.title`). All messages
  share one namespace and the last loaded wins on a collision.
- **Anything that outlives an area** - a header, a toast queue - must read from the app's own
  messages; an area's keys stop resolving once you leave it.
- **imp does not persist the language.** Store the choice and pass it back as `init({ lang })`.

## Component wording

The standard components of [std](std.md) look their words up under an `imp.` key with English as the
fallback, so they read properly with no translation files at all. Writing that key in your own files
wins, per key and per language:

```js
// locales/pl.js
export default { imp: { state: { empty: 'Nic tu jeszcze nie ma' } } }
```

| Key                   | Read by                                | Falls back to    |
| --------------------- | -------------------------------------- | ---------------- |
| `imp.state.empty`     | `emptyState`                           | Nothing here yet |
| `imp.state.noResults` | `emptyState({ variant: 'noResults' })` | No results       |

Your own components carry wording the same way with `defaultMessages` - a **flat** object of dotted
keys to strings, called where the component defines itself (not at module top level, so an unused
module stays side-effect free):

```js
let create = null
export const trialNotice = (...args) => {
  if (!create) {
    defaultMessages({ 'billing.trialEnded': 'Your trial has ended' })
    create = component('my-app-trial-notice', definition)
  }
  return create(...args)
}
```

## Direction

`init` sets `<html dir>` and every `setLang` moves it; direction comes from the **script**
(`az-Arab` is rtl, `az-Latn` is ltr). Write CSS in logical properties - `margin-inline-start`,
`padding-inline-end`, `inset-inline-start`, `text-align: start/end` - and one stylesheet serves
both. Pin the whole app with `init({ dir: 'ltr' })`, one element with `pre({ dir: 'ltr' }, code)`,
and let the browser decide for user-typed text with `p({ dir: 'auto' }, comment.body)`.

## Area translations

An area - see [routing](routing.md) - declares its own messages alongside its routes; entering it
loads the one file matching the current language before its first screen paints, and switching
language loads the area's messages alongside the app's.

```js
export default area({
  routes: { '/': () => dashboard() },
  translations: { en: () => import('./locales/en.js'), pl: () => import('./locales/pl.js') },
})
```

## Testing

See [testing](testing.md) for the runner.

```js
beforeAll(() => init({ translations: { pl: () => import('./locales/pl.js') } }))

test('greets in the active language', async () => {
  await setLang('pl')
  expect(t('greet')).toEqual('Cześć')
})
```
