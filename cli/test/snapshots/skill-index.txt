imp skills — the usage manuals imp ships for the agent writing the code

imp is a buildless UI toolkit: your ES modules run in the browser exactly as written — no
compile step, no JSX, no bundler in development. Everything an app uses arrives through a
bare specifier imp resolves ('imp', 'imp/html', 'imp/state', …), and the same imp binary
serves, tests, lints, formats and builds the project.

Read one in full — no flags, the text goes to stdout:

  imp skill state                  a subject listed below (several at once is fine)
  imp skill std/button             a standard component
  imp skill ./src/counter.js       a component of this project, by path to its module

WRITING AN APP
  imports         every bare specifier imp resolves, and what each one exports
  rendering       element factories, props objects, children, and mount
  components      custom elements with an onMount lifecycle: instance, styles, cleanup
  state           named reactive state shared down the tree and bound straight to the DOM
  routing         client-side routes as one plain-data table, with lazily loaded sections
  std             the built-in component library: button, heading, text, link, emptyState
  theming         themes as plain token modules, applied at the entry point and swappable
  i18n            t() lookups, per-language messages, and the lang attribute that drives them
  logging         the built-in logger and the per-environment log level

WORKING IN AN IMP PROJECT
  cli             every command, imp.json configuration, the dev server and the production build
  testing         unit tests in-process and e2e specs against a real browser
  dependencies    vendoring packages into dependencies/ and importing them
  lint            the imp lint rules, what each one prevents, and how to apply fixes
  fmt             formatting every file type in the project with one command

STANDARD COMPONENTS — imported from 'imp/std' · read: imp skill std/button
  std/button      button — the standard button, rendered as a real `<button>`
  std/heading     heading — a section heading, rendered as the real `h1`–`h6` element
  std/text        text — body text, a paragraph by default or an inline span
  std/link        link — a real anchor whose in-app clicks are handled by the router
  std/emptyState  emptyState — the placeholder for a list, table or search result with nothing in it

THIS PROJECT — components with a skill file · read: imp skill ./path/to/component.js
  ./test/fixtures/skill-project/counter.js  counter — a self-contained increment/decrement widget

A component documents itself in a 'counter.skill.md' file next to it — write one for every
component you build, and an agent can learn it the same way it learns imp. 'imp help' lists
every command; run 'imp lint' and 'imp fmt' when you are done editing.
