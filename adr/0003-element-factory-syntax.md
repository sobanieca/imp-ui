# 0003 — Element-factory syntax, no JSX or templates

**Status:** Accepted

## Context

DOM structure has to be expressed somehow. The mainstream options are JSX (requires a
compile/transpile step), tagged-template HTML strings (`html\`<div>...\``, parsed at runtime), or
plain function calls. imp-ui is buildless by essence (#1) — plain ES modules in the browser, no
transpilation ever — which rules JSX out immediately. Template strings keep buildlessness but
reintroduce a parser, a second (HTML-shaped) syntax to learn, and string-y interpolation that is
awkward to compose programmatically.

## Decision

DOM is expressed as **JavaScript function calls** (essence #7):

- `el(tag, ...args)` is the single primitive.
- Per-tag shortcuts (`div`, `p`, `button`, … ~80 tags) are thin wrappers over `el`, generated from a
  tag list.
- `svg.*` is a proxy producing SVG-namespaced elements, with attributes set verbatim so
  case-sensitive names (`viewBox`) round-trip.

No JSX, no string templates. Components are just lowercase functions that call these factories and
return nodes (essence #14).

## Consequences

- Zero build step; the same code that ships runs in the editor, tests, and browser unchanged.
- Composition is ordinary JavaScript — `map`, spread, conditionals, helper functions — with no
  template/expression boundary to cross.
- The tag-shortcut list is a fixed export surface; tags outside it use `el('tag', ...)` (or
  `svg.tag`). Adding a shortcut is a one-line list edit.
- The trade-off is verbosity versus HTML-like markup, and an export surface of ~80 names. Accepted:
  function calls are what agents generate most reliably and what composes without special-casing.
- Because shortcuts are generated by destructuring a map, every tag behaves identically to `el` —
  there is no per-tag special behavior to document.
