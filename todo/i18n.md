# Internationalization — translatable by default

Make imp translatable by default: a reactive `locale` signal plus `t()` and Intl-based number/date
formatters, so changing locale re-localizes only the affected text nodes live — no re-render, no
external i18n dependency (essence #18 in `prev/essence.md`). A working draft is
`prev/experiment/imp/i18n.js`.

## Reactive by construction

`locale` is an app-lifetime state owned by the app's root component; `t()`/`n()`/`d()`/`rt()` read
it. Used inside a state binding (`locale.text(() => t('todo.title'))`), the text node re-localizes
itself when the locale changes — exactly the fine-grained update path of the landed state layer
(`adr/event-propagated-state.md`).

## Pieces (port from the draft)

- `locale` signal + `setLocale(loc)`; `setFallbackLocale(loc)` (default `en`).
- `defineMessages(loc, messages)` — registers a **flat** catalog per locale
  (`{ 'todo.title':
  'Todos' }`; dots are plain characters, no nesting). Calls merge into the
  existing catalog for that locale.
- `t(key, params)` — lookup with fallback chain (exact locale → base language `en-US`→`en` →
  fallback locale → the key itself). A message may be a **plural-forms object**
  (`{ zero?, one, two?,
  few?, many?, other }`) selected via `Intl.PluralRules` on `params.count`;
  `{name}` placeholders interpolate from `params` (numbers localized with `toLocaleString`).
- `n(value, opts)` — `Intl.NumberFormat`.
- `d(date, opts)` — `Intl.DateTimeFormat`.
- `rt(date)` — `Intl.RelativeTimeFormat`, largest fitting unit ("5 minutes ago").

Keep the module pure (its only dependency is the signal graph) so it is testable in isolation and
runs under the `imp test` DOM stubs.

## Interaction with theming and the stdlib

- **Theming:** theming (`adr/themable-by-default-tokens.md`) deliberately owns no direction axis —
  the theme engine touches `dir` not at all, leaving it entirely to i18n. Direction resolution lands
  here: derive it from the current locale (`Intl.Locale` text-info, RTL language list fallback) and
  set the document `dir`, while the stdlib's logical-properties styling rule mirrors layouts for
  free.
- **Stdlib:** every stdlib component pipes its user-facing strings through `t()` and seeds defaults
  via `defineMessages` (the draft `stdlib/index.js` registers `imp.close`, `imp.loading`,
  `imp.empty`, `imp.prev`, `imp.next`, `imp.page`). Apps override those keys per locale.
  `todo/stdlib-components.md` depends on this layer.

## ADR impact

New ADR `translatable-by-default.md`: `locale` as a signal driving live re-localization, flat
dot-keyed catalogs with a language-fallback chain, plural-forms objects + `{name}` interpolation,
and Intl-based number/date/relative-time formatting. Update the ADR table; document usage and the
built-in stdlib message keys in `docs/`.

## Open questions

- **Catalog loading.** Whether locales are only registered imperatively via `defineMessages`, or imp
  offers a convention for lazy-loading a locale's catalog on demand (dynamic `import()`, buildless).
- **Missing-key policy.** The draft falls back to returning the key; decide whether a dev-mode
  warning (through the built-in logger, `todo/logger.md`) should flag missing translations.
- **Message extraction / lint.** Whether a lint rule should catch `t('…')` calls whose key is absent
  from the base catalog, mirroring imp's other static checks.
- **`rt` auto-refresh.** `rt(date)` formats once; live "n minutes ago" tick-updating is out of scope
  unless a component opts in via a signal.
