# PWA offline fallback page - a branded offline page for uncached navigations

When the network is unavailable and the requested navigation is not in the cache, the service worker
emitted by `imp build --pwa` (`buildServiceWorker` in `cli/src/pwa.js`) falls back to the cached app
shell (`SHELL`). That is the right behavior for an app-shell SPA where the shell can render any
route, but it is wrong for a multi-page app or any deep link the shell cannot render offline - the
user gets the shell chrome around nothing, or a broken page, instead of an honest "you're offline"
screen.

## Proposal

Precache a dedicated offline fallback document and serve it (instead of, or in addition to, the app
shell) when a `navigate` request cannot be satisfied from the network **or** the cache. Cheap to
build, high-value, and squarely in the opinionated-default spirit of `adr/pwa-toolkit.md`.

## Pieces

- **A default fallback page**, generated by the build so every `--pwa` app gets one with no work -
  branded from the existing `pwa` block (`name`, `themeColor`, `backgroundColor`, icon) so it
  matches the app without author input.
- **An optional override**: a `pwa.offline` path in `imp.json` pointing at the author's own HTML,
  precached in its place when present.
- **Fetch-handler wiring**: on a `navigate` request, try network -> cache (shell/deep link) ->
  offline fallback, in that order, so a cached deep link still wins and the fallback is the last
  resort.

## Open questions

- Whether the fallback replaces the app-shell fallback entirely or is only used when there is no
  cached shell match - interacts with whether the app is SPA-style (shell renders everything) or
  multi-page.
- Whether to precache one offline page or allow per-scope fallbacks (probably out of scope - one
  page).
- Asset budget: the fallback should be self-contained (inline CSS, embedded icon) so it never
  depends on other cached assets that might be missing.

## ADR impact

Update `adr/pwa-toolkit.md`: fold this into the _Scope and non-goals_ section (remove it from the
open items), note the added `pwa.offline` option if adopted, and document the offline fallback in
`docs/`.
